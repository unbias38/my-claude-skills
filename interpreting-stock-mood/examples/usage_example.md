## 範例 1：清楚提問 → 直接分析

**使用者輸入：**
```
我手上 2330 已經持有 2 年，平均成本 600 元，現在想加碼，他現在是好時機嗎？
```

**Claude 處理流程：**

1. **判斷提問是否模糊**：使用者已包含「持倉狀態（已持有）+ 成本（600）+ 想做什麼（加碼）+ 標的（2330）」 → **不需要反問**，直接進分析。

2. **跑腳本**（先猜中文搜尋詞為「台積電」）：
```bash
python "<SKILL_DIR>/scripts/analyze_stock.py" "2330" "台積電"
```

3. **腳本回傳（節錄）**：

4. **載入 references**：
   - `technical_emotion_mapping.md` 全部
   - `asset_traits.md` 的【大型權值股】+【AI 概念股】段落（2330 屬於這兩類）

5. **產出**：

```markdown

**標的**：2330.TW 台積電
**你的提問**：他現在是好時機加碼嗎？

- 趨勢面：均線多頭排列（5MA > 20MA > 60MA）+ 站上所有均線 + 位於 60 日區間頂端 99%
- 動能面：RSI 72.7（超買區邊緣）+ MACD 多頭氛圍持續
- 量能面：量縮價漲（漲勢的「能量」開始降低，不一定立刻反轉但要留意）
- 新聞面：AI 訂單能見度延伸的利多新聞，呼應價格表現
- 社群面：Google Trends 上升，散戶關注度跟著漲

---

### 2️⃣ 他想說什麼（擬人化推測）

> 「我幫你問了台積電哦 ——

---

### 3️⃣ 建議行動

針對你的提問「現在是好時機加碼嗎？」+ 你的處境（已持有 2 年、成本 600、想加碼）：

- ✅ **你的成本低（600 vs 現價 2305）**，意思是即使現在加碼到平均成本被拉高，整體部位仍然是健康的賺錢狀態，這給你不少緩衝空間
- ✅ 可以考慮**分批加碼**而不是一次梭哈：例如分 3-4 次在不同時點進場，平均掉「短期過熱」的風險
- 🤔 **觀察訊號**：
  - 量價關係能不能從「量縮價漲」轉回「量增價漲」？前者是動能不足
  - RSI 是否會從超買區（> 70）拉回到 50-60 之間？通常那是更舒服的進場點
  - 60 日線（約 1952）是中期支撐，回測時是否有撐
- ⚠️ **沒有警訊（warnings 為空），但區間位置太頂端要小心追高**

> ⚠️ **本分析僅為技術面解讀與娛樂用途，非投資建議。投資決策請自行評估並承擔風險。**
```

## 範例 2：模糊提問 → 先反問再分析

**使用者輸入：**
```
台積電最近都不太理我
```

**Claude 應該回應：**

```markdown
我可以幫你跟 2330 台積電溝通看看 🎧，不過為了讓分析更貼合你的處境，先問你 4 件事：

1. 📦 **你目前的持倉狀態**？
   - (a) 已經持有 (b) 還沒買，正在考慮 (c) 想賣，正在考慮 (d) 純粹好奇

2. 🧭 **你的方向偏好**？
   - (a) 看好（想長期持有 / 加碼） (b) 看壞（想停損 / 放空） (c) 不確定 (d) 跟著市場走就好

3. 💰 **金額或部位規模**（隨意，可只說大概）？
   - 例：已投入 10 萬 / 想投入單筆 / 佔資產 20% / 不重要

4. ⏳ **時間範圍**？
   - (a) 短線（一個月內） (b) 中線（半年內） (c) 長線（半年以上） (d) 沒概念

你回答後我再進行完整分析（後台會自動抓股價、新聞、社群熱度）。
```

**等使用者回答後**，再走範例 1 的完整流程。

## 範例 3：使用者輸入不完整（沒給代號）

**使用者輸入：**
```
他最近怎麼了，我想知道
```

**Claude 應該回應：**

```
我可以幫你跟股票溝通師問問！需要知道：

1. 📊 **股票代號**：你想問哪一檔？（例：2330、0050、AAPL、QQQ）
2. ❓ **你想問什麼**：例如「他在生氣嗎」「他是不是要噴了」「我該不該停損」

兩項補上之後就可以開始分析。
```

不要在缺少資訊時自己編股票代號或亂猜情緒。

## 範例 4：容錯場景 — pytrends 被擋

**腳本回傳（節錄）**：
```json
{
  "trends": null,
  "trends_error": "pytrends 錯誤（可能被 Google 暫時擋住）：The request failed: Google returned a response with code 429"
}
```

**Claude 在輸出時**：

```markdown
### 🌐 社群熱度（Google Trends）
- **無資料**（Google Trends 暫時不可用，可能是短期內查詢過多被暫時封鎖）

> 為什麼有這一段？因為 pytrends 是非官方爬蟲，Google 偶爾會限速，
> 我們的 skill 設計成「失敗就跳過」，不會中斷整體分析。
> 你可以等 5-10 分鐘再試一次。
```

不要因為 trends 失敗就不輸出整份報告，其他資料（價格、技術指標、新聞）照常顯示。

## 設計巧思：為什麼這個 skill 適合教學工作坊？

把這個範例當作教材時，可以引導學員注意：

1. **同一個「骨架」可以遷移到完全不同的領域**
   - 從「跟寵物溝通」到「跟股票溝通」，工作流程結構幾乎相同
   - 這就是「重用 skill 設計」的典範

2. **AI 玄學的識破練習**
   - 範例 4 的 trends 失敗顯示：當資料缺乏時，誠實標「無資料」遠勝編造
   - 對比一下：如果是廣告化的 AI 投資工具，會不會在沒資料時還硬講？

3. **擬人化包裝 + 客觀內核**
   - 範例 1 的「他自己都覺得有點頭暈了」聽起來像玄學，但每一句都對應一個技術指標
   - 這個對比是教學重點：**有溫度的輸出**不等於**沒根據的輸出**

4. **強制免責設計**
   - 每份分析都帶著「非投資建議」字樣
   - 這是一個社會責任的設計選擇 — 即使是娛樂工具，也不能誤導
