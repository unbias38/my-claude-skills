## 範例 4：容錯場景 — 資料源抓取失敗（PTT 解析失敗 + pytrends 被擋）

**腳本回傳（節錄）**：
```json
{
  "ptt_heat": null,
  "ptt_error": "PTT 抓到頁面但解析出 0 篇標題（HTML 結構可能改版）",
  "trends_error": "pytrends 錯誤（可能被 Google 暫時擋住）：The request failed: Google returned a response with code 429"
}
```
（注意：`trends` 這個 key **完全不存在**，只有 `trends_error` 留給 debug。）

**Claude 在輸出時**（依 SKILL.md 規則 A/B/C — 透明 > 隱藏，但失敗不納入判讀）：

1. **多維熱度表**：`ptt_heat` 為 null → 散戶熱度那一列**保留**並標「⚠️ 抓取失敗（未納入判讀）」；`trends` 為 null → **整列「Google Trends」不顯示**（次要欄位，不標失敗）。

```markdown
| 維度 | 指標 | 訊號 |
|---|---|---|
| 🧑‍🤝‍🧑 散戶熱度 | PTT 股板 | **⚠️ 抓取失敗（未納入判讀）** |
| 🌟 知名度 | Yahoo 留言累計：25,300 則 | 高知名度 |
| 📰 媒體熱度 | 近 3 日新聞 6 則 | 密度高 |
| 💰 市場熱度 | 量比 20MA：0.72× | 量縮價漲 |
| 🏛 法人方向 | 外資/投信/自營 | 三大法人合計買超（偏多） |
```

2. **交叉判讀**：完全跳過需要散戶維度的判讀條目（規則 C），**不可以**產生「散戶冷清 + 法人買超 = 法人悄悄佈局」這種基於失敗的誤判，並加一行說明：

```markdown
**交叉判讀**：
> 📰 近 3 日新聞密集 + 股價上漲：可能有事件驅動
>
> （PTT 抓取失敗，散戶熱度未納入此次交叉判讀）
```

3. **PTT 範例討論子段**（規則 B）：寫一行「**⚠️ PTT 抓取失敗**」即可，不編造標題。

4. **其他區塊照常輸出**：價格、技術指標、新聞、法人都有抓到，整份五區塊報告 + 📌 一句話總結照常產出，**不因單一資料源失敗而中斷**。

❌ **不要**另開獨立的「🌐 社群熱度（Google Trends）：無資料」段落 —— 「真的冷清」和「抓取失敗」意義差很多，失敗就是標失敗（或整列不顯示），不能長得像一個有內容的分析段。

## 設計巧思：為什麼這個 skill 適合教學工作坊？

把這個範例當作教材時，可以引導學員注意：

1. **同一個「骨架」可以遷移到不同的領域**
   - 「給輸入 → 抓多源資料 → 萃取特徵 → 擬人化包裝 + 客觀內核 → 強制免責」這個流程是可複用的 skill 設計骨架
   - 把資料源換掉、把領域換掉，骨架不變

2. **AI 玄學的識破練習**
   - 範例 4 顯示：資料源失敗時，誠實標「⚠️ 抓取失敗（未納入判讀）」並在交叉判讀中跳過該維度，遠勝把「沒抓到」講成「真的冷清」
   - 對比一下：如果是廣告化的 AI 投資工具，會不會在沒資料時還硬講？

3. **擬人化包裝 + 客觀內核**
   - 範例 1 的「他自己都覺得有點頭暈了」聽起來像玄學，但每一句都對應一個技術指標
   - 這個對比是教學重點：**有溫度的輸出**不等於**沒根據的輸出**

4. **強制免責設計**
   - 每份分析都帶著「非投資建議」字樣
   - 這是一個社會責任的設計選擇 — 即使是娛樂工具，也不能誤導
