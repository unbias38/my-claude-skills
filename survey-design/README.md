# 學術問卷設計師 / survey-design

一個 Claude Code skill —— 幫你設計達到學術發表水準的問卷/量表：從構念定義、題目撰寫、問卷結構，到用 120 分自評量表打分數並自動修到及格，最後產出「給填答者的問卷 + 給研究者的文件 + 給專家的內容效度評定表」三份檔案。

## 為什麼需要它

自己編問卷很容易踩坑：雙重題意（一題問兩件事）、引導性措辭、選項重疊、反向題亂放……這些缺陷在投稿時會被審查委員抓出來，甚至讓整份資料白收。這個 skill 把 COSMIN、Dillman 等問卷設計方法論做成 Claude 會自動遵守的規則，設計完還會**自己打分數、自己修**，交出來的就是可以直接送專家評審的草稿。

## 它做什麼

分成兩個階段：

**階段一：對齊（會停下來問你）**

先跟你確認最關鍵的一步——構念定義。Claude 會提出：

1. 構念的操作型定義（附文獻依據）
2. 與相近概念的區分（例如焦慮 vs 壓力）
3. 既有量表回顧——如果已經有合適的量表，會**建議你直接採用**而不是重造輪子
4. 子面向拆解 + 題目藍圖（每個面向預計幾題）

你確認或調整後才往下走。

**階段二：執行（一路自動做完）**

1. 依 Dillman 原則設計每一題（一題一事、措辭中立、明確時間框架、反向題不超過 2-3 成）
2. 排版問卷結構：指導語、分節、題目順序（簡單題開頭、敏感題後放、人口變項壓軸）、必要時加篩選題
3. **自評 + 自動補救迴圈**：對照 24 項評分規準（滿分 120）逐項打分，低於 3 分的項目自動修正、重評，最多跑 3 輪；修不好的會誠實標出來問你怎麼辦
4. 產出三份檔案 + 在對話中交付自評成績單、修訂紀錄、後續建議步驟

### 產出的三份檔案

輸出在**你的工作目錄**的 `output/` 資料夾（不會寫進 skill 資料夾）：

| 檔案 | 給誰看 | 內容 |
|------|--------|------|
| `questionnaire.md` | 填答者 | 乾淨的問卷本體，無任何變數名稱或計分資訊 |
| `documentation.md` | 你（研究者） | 構念定義、量表回顧、設計決策、變數編碼表（codebook）、計分方式 |
| `expert-review-form.md` | 領域專家 | 內容效度評定表（CVI 法），附 I-CVI / S-CVI 計算表格 |

## 怎麼觸發

跟 Claude 說類似這些話就會啟動：

```
我要設計一份測量「遠距工作倦怠」的問卷，要投期刊用
幫我編一份 Likert 量表測學生的學習動機
我想做量表發展（scale development），構念是數位素養
幫我設計問卷，對象是台灣的國中教師
```

只要提到問卷設計、量表發展、構念測量、Likert 量表、心理計量工具等，即使沒說「survey design」也會觸發。

開始前 Claude 會確認四件事（缺了會問你）：研究目的、要測什麼構念、目標族群、問卷語言。

## 範圍界線

這個 skill 做到「**可送專家評審的設計草稿**」為止。以下是交付後你自己接手的步驟，不在範圍內：

- 統計驗證（EFA / CFA、信度分析、項目分析）
- 資料收集（專家評定、認知訪談、預試）
- 問卷平台上架

交付時會附建議的後續步驟（送 5-7 位專家評 CVI → 30-50 人預試 → 因素分析）。

## 安裝

把資料夾複製到 Claude Code 的 skills 目錄即可，零依賴、不用裝任何東西：

```
~/.claude/skills/survey-design/            # 全域可用
# 或
<專案>/.claude/skills/survey-design/       # 只在該專案啟用
```

裝完重啟 Claude Code。詳細安裝指令（含 Windows）見 [repo 根目錄 README](../README.md#安裝)。

## 檔案結構

```
survey-design/
├── SKILL.md                          ← Claude 讀的工作流定義（兩階段流程 + 自動補救迴圈）
├── README.md                         ← 你正在讀這份
├── references/
│   ├── cosmin.md                     ← COSMIN 內容效度框架 + CVI 計算門檻
│   ├── dillman.md                    ← Dillman 題目撰寫與問卷結構原則
│   ├── common-pitfalls.md            ← 常見缺陷清單（雙重題意、引導措辭…附修正方式）
│   └── rubric.md                     ← 24 項自評量表（8 面向、滿分 120、含等級判定）
└── assets/
    └── expert-review-template.md     ← 專家內容效度評定表模板（CVI 法）
```

## 設計原則

- **對齊一次，執行到底**：只在構念定義這一步停下來等你確認——因為這步錯了整份問卷都白做；確認後就一口氣做完，不會每題都煩你。
- **誠實自評**：打分數是為了找弱點，不是灌分。修不到 3 分的項目會標出來說明原因，不會硬凹。
- **不過度優化**：補救迴圈只修既有題目，不會為了衝分數亂加題或動架構；一個修法會傷到另一個指標時，會說明取捨而不是兩頭硬追。
- **每個決策可回溯**：所有設計選擇都對得上 `references/` 裡的方法論依據。
- **不重造輪子**：既有量表夠用就建議採用並教你怎麼正確引用改編。
