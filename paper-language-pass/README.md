# 論文語言把關 / Paper Language Pass

一個 Claude Code skill —— 針對**科學內容已定案**（同儕審查已過、實質問題已回覆）的英文學術稿件，出動 8 個平行 subagent 各掃全文一個維度（一致性、時態、語氣強度、句子品質、連貫性、摘要、稿件衛生、AI 味），彙整成一份依嚴重度排序的編號問題清單，**等你核可後才動任何檔案**。

## 為什麼需要它

投稿前的最後一輪語言檢查，靠一個人（或一個 AI）從頭讀到尾，注意力一定顧此失彼：盯著時態就漏掉縮寫不一致，改句子就忘了摘要和內文的說法對不上。這個 skill 把檢查拆成 8 個獨立維度，每個維度由一個專職 subagent 讀完**整篇**稿件只找那一件事，最後再合併成一份可以逐條決定要不要改的清單。

另外，越來越多期刊會篩「看起來像機器寫的」稿件。本 skill 的 Pass 8 專門量測這件事——用全文密度數字，不用直覺。

## 它做什麼

### 8 個平行 Pass

| Pass | 檢查者 | 找什麼 |
|---|---|---|
| 1 | 一致性稽核 | 術語 / 縮寫 / 大小寫 / 數字 / 單位 / 連字號是否全文一致 |
| 2 | 時態稽核 | 各章節時態是否符合慣例、章節內是否一致、et al. 的動詞單複數 |
| 3 | 語氣稽核 | 主張強度是否和證據相稱：過度宣稱、hedging 不足或過度、摘要與內文不一致 |
| 4 | 句子品質（只檢查不改寫） | 文法、名詞化、贅字、冗長、彆扭措辭——**只看句子層級** |
| 5 | 連貫性 | 段落是否主張先行、轉場、論證串接、內容重複或放錯位置 |
| 6 | 摘要稽核 | WHY→PROBLEM→HOW→RESULTS 結構、縮寫展開、不引文獻、單一段落 |
| 7 | 稿件衛生 | 三類「從別的文類滲進來」的句子：(A) 審稿流程的後設語言、(B) 對期刊的自我指涉 / 恭維、(C) 工程實作細節外洩（含沒走到的 fallback 路徑） |
| 8 | AI 味稽核 | 8 個 tell 家族的**全文密度**：吹捧語氣、自創術語、評價副詞開頭、程序式段落路線圖、論點重複回收、破折號密度、招牌詞彙、機械式修辭模板。回報一個 **signature score**（8 個家族中幾個「開火」） |

每個 Pass 的完整檢查清單、人設、嚴重度標準都在 `references/pass1` 到 `pass8` 的獨立檔案裡，subagent 直接讀檔當作指令，SKILL.md 只負責調度與彙整。Pass 之間的邊界是明文寫死的（例如「證據撐不撐得起這個主張」歸 Pass 3，「不看證據、語氣本身就浮誇」歸 Pass 8），避免同一句話被兩個 Pass 重複開單。

### 為什麼 AI 味用「數字」判定

一個 `Notably,` 是一個詞；十一個是一種習慣。一個破折號是標點；每千字 4.6 個是指紋。所以 Pass 8 不逐句挑，而是量測**全文密度**，每個家族有各自的開火門檻，低於門檻就不會被大量標記正常英文。而且它只回報「這個模式的出現率是常態的 N 倍、有審稿人觀感風險」，**永遠不會斷言稿子是 AI 寫的**。

修的時候也是「降到正常值，不是歸零」：破折號目標約每千字 0.5 個，刮到 0 反而看起來像洗過稿，那本身又是另一種訊號。

### 兩階段工作流

```
Phase 1（只偵測）                          Phase 2（經核可才執行）
┌─────────────────────────┐               ┌─────────────────────────┐
│ 8 個 subagent 平行掃描    │   你核可後    │ 只改你同意的項目          │
│ → 合併成編號清單          │  ─────────→  │ 最小幅度修改，不重寫       │
│ → 依嚴重度分級            │              │ .docx 用追蹤修訂          │
│ → 給分級修改建議 + 選單    │              │ → 回報修了幾條、跳過幾條   │
└─────────────────────────┘               └─────────────────────────┘
```

Phase 1 結束會給你一個選單，例如：

- `fix critical only` —— 只修 CRITICAL（保守路線，趕投稿用）
- `fix ai tells` —— 只修 Pass 8 有開火的家族，修完附前後密度對照表
- `proceed with all, discard 1-3, 4-12` —— 全修但跳過指定編號
- `build my discard list` —— 請 Claude 依建議先幫你草擬一份跳過清單
- `nothing — I'll fix manually` —— 只拿報告，不動檔

在你回覆之前，**任何檔案都不會被修改**。

### 期刊規則校準

這個 skill 不預設任何學科的慣例。開始前會問一次（不逐項逼問）目標期刊的已知規則——摘要能不能引文獻、字數上限、Methods/Results 時態、英式或美式拼字、hedging 預設強度、AI 味檢查敏感度（`standard` / `strict` / `relaxed`）等。不知道的就填 `unspecified`，該項會退回一般學術預設，且對應的警告從 CRITICAL 降為 MAJOR，並建議你自己核對 2–3 篇目標期刊近期論文。

## 怎麼觸發

拿一份接近完稿的稿件（`.docx`、`.md` 或 `.tex`），跟 Claude 說：

```
幫我對這篇論文做 language pass
潤稿，投稿前最後檢查
polish my paper / proofread my manuscript
幫我檢查時態和 hedging
這篇有沒有 AI 味？看起來像不像 AI 寫的？
```

可以只跑部分 Pass（例如「只跑 Pass 2 和 3」）。如果你的問題是「這篇像不像 AI 寫的」，skill 會跑 Pass 8 加上 3、4、5——tell 的數字搭配語氣和連貫性的發現一起看才好解讀。

**不適用**：初稿撰寫、內容審查、科學批判、統計檢查（那些是上游的事）；**中文稿也不適用**——本 skill 的檢查（拼字、時態、冠詞、hedging 動詞）都是英文專屬，中文稿的去 AI 味請改用 `humanizer-zh-tw`。

## 安裝

把資料夾複製到 Claude Code 的 skills 目錄即可，skill 本身零依賴：

```
~/.claude/skills/paper-language-pass/            # 全域可用
# 或
<專案>/.claude/skills/paper-language-pass/       # 只在該專案啟用
```

裝完重啟 Claude Code。詳細安裝指令（含 Windows）見 [repo 根目錄 README](../README.md#安裝)。

**格式相關的條件需求**：

| 稿件格式 | 額外需求 |
|---|---|
| `.md` | 無 |
| `.tex` | 無（會自動遞迴跟進 `\input{}` / `\include{}`） |
| `.docx` | 需要 `docx` skill 或 pandoc（用來轉出純文字給 subagent 讀；修改則以**追蹤修訂**寫回原檔） |

    ├── pass3-hedging.md                  ← 語氣強度稽核

    ├── pass5-coherence.md                ← 連貫性審查

    ├── pass7-manuscript-hygiene.md       ← 稿件衛生（文類滲漏）

## 設計原則

- **先偵測，後修改**：使用者沒核可之前不動任何檔案。
- **一個 agent 只看一個維度**：避免「一個 agent 什麼都查」導致的清單失焦；每個 agent 也被明確告知哪些**不是**它的工作。
- **保留作者的聲音**：Phase 2 只做能解決該問題的最小修改，不整句重寫；作者的節奏屬於作者。
- **模式訊號 ≠ lint 錯誤**：破折號、三段式列舉、對稱句型在適量時都是正常學術英文，只有機械式群聚才是訊號。單一出現不開單。
- **量測後才下判斷**：Pass 8 連沒開火的家族也回報數字，讓作者看到「差多遠」而不是只拿到一個結論。
- **回報觀感風險，不回報作者身分**：輸出永遠是「此模式出現率為常態 N 倍」，不是「這是 LLM 寫的」。
- **稽核結果是候選清單，不是必修清單**：8 個 subagent 是模式比對器，分不出某個名詞化是彆扭還是該領域慣例——最後判斷權在作者。
